# ソースコード（自分が担当した範囲の抽出）

ハッカソンで自分が書いたコードのうち、**他のメンバーが1行も触っていないファイル**だけを
取り出したものです。公開は主催元の許可を得ています。

## 含めているもの・いないもの

| | 扱い |
|---|---|
| 提出時点で自分が単独で書いたファイル（42件） | そのまま置いています。提出したものと同じ内容です（テストデータとデモ投稿の店名・地名・住所・座標のみ、架空の名前と、大阪駅・京都駅の周辺の座標に置き換えています。位置どうしの距離は保っています） |
| このリポジトリのために書いた補助実装（5件） | 下の「補助実装について」に一覧があります |
| ハッカソン後に足した改良（7件。実装5、テスト2） | `src/improvements/` と `tests/improvements/` にあります |
| 単体で動かすための設定など（6件） | `package.json`、`package-lock.json`、`tsconfig.json`、`.gitignore`、架空データの `data/posts.json`、この README |
| 他のメンバーが書いた、または共同で編集したファイル | **含めていません** |
| 主催元から配布された資料、企画資料、審査の資料そのもの | **含めていません**（審査で受けた指摘の要旨は、[リポジトリのREADME](../README.md#アイデアソンからの経緯)に自分の言葉で書いています） |
| git の履歴 | 引き継いでいません。他のメンバーの氏名とメールアドレスが混ざるためです |
| デモ用の利用者データ | 架空です。自分の名前に由来する表示名も中立な名前に置き換えています |

`source/` 配下は合計60ファイルです（42 + 5 + 7 + 6）。42件の一覧は
[scripts/extract_from_team_repo.py](../scripts/extract_from_team_repo.py) の `EXPECTED_FILES` にあります。

## 補助実装について

自分が書いたファイルは、チームの他メンバーが書いたモジュールを参照しています。
それらは含められないため、**単体で動かすための最小実装をこのリポジトリのために新しく書いて**
同じ場所に置いています。該当するのは次の5ファイルで、いずれも先頭に「補助実装」と明記しています。

- `backend/src/server.ts`
- `backend/src/routes/posts.ts`
- `backend/src/services/distanceService.ts`
- `backend/src/services/postService.ts`
- `backend/src/types/post.ts`

これらは元の実装を写したものではありません。自分が書いたテストが求める振る舞いから
書き起こしています。投稿の作成・いいね・コメントの書き込み処理は、自分の担当範囲では
ないため実装していません（公開範囲の判定で弾くところまでです）。

`backend/data/posts.json` も、テストが必要とする位置関係を満たす架空のデータとして
作り直したものです。

### フロントエンド（Flutter）

利用者一覧、プロフィール、フォローリクエストの画面と、地図の選択カード、
現在地アイコン、フォローボタン、利用者切り替えなどの部品。およびそのテスト。

このリポジトリには Flutter のプロジェクト設定を含めていないため、
`frontend/` 配下は**読むためのもの**です。ビルドはできません。

地図画面の本体（`lib/screens/map_screen.dart`）は他のメンバーと共同で編集したため収録していません。
`test/map_grouping_test.dart` はこの画面にある、同じ場所の投稿を1つのピンにまとめる処理
（`MapScreen.groupPosts`）を対象にしたテストです。テストは自分が単独で書いたので収録していますが、
対象のコードはこのリポジトリにはありません。他のテストが参照している投稿のモデル
（`lib/models/post.dart`）と API クライアント（`lib/services/api_client.dart`）も、同じ理由で収録していません。

投稿・コメントの削除も、本体は共同で編集したファイルにあるため収録していません。
収録しているのは、削除のときに画像ファイルを消す処理（`src/utils/upload.ts`）までです。

## ハッカソン後に足したもの

`src/improvements/` 配下は、ハッカソン終了後に自分ひとりで書いたもの。
提出時点のファイルには手を入れていないので、当時のコードとテストはそのまま残っています。

### 踏破率（`improvements/coverage/`）

「半径を絞ると、知らなかった場所が見つかる」という主張を数字で裏づける。

```
GET /api/coverage?latitude=&longitude=&userId=&radius=&limit=

半径5km以内に123か所。行ったことがあるのは18%で、残り101か所は未訪問です。
```

あわせて、未訪問の場所を近い順に返し、半径1.5km / 5km / 20km での候補数を並べる。
広げるほど候補は増えるが、増えた分は「今日行ける場所」ではない、という対比を出すため。
場所の取得にはハッカソンで書いた `placesService` をそのまま使っている。

### ログイン（`improvements/auth/`）

提出時点では操作者をクライアントの申告（`userId` など）で受け取っていた。
誰でも他人を名乗れるため、公開範囲をサーバー側で判定していても鍵アカウントが成り立たない。

- パスワードは scrypt で導出した鍵だけを保存する
- セッションは識別子だけを Cookie に入れ、中身はサーバー側に置く（失効を効かせるため）
- Cookie は HttpOnly、SameSite=Lax、本番は Secure
- 利用者IDの誤りとパスワードの誤りを区別せず、存在する利用者IDを外から調べられないようにする
- 身元はルーターの手前で上書きする。提出時のルーターに手を入れずになりすましだけを塞ぐため

既定では無効にしてある。提出時点の動きを残し、当時のテストがそのまま通るようにするため。
有効にするには `createApp({ requireAuth: true })` を使う。

```bash
npm test   # 提出時点のテストと、追加したテストの両方が走る
```

## 動かし方（バックエンド）

```bash
cd source/backend
npm install
npm test        # 自分が書いたテストを実行する
npm run dev     # http://127.0.0.1:3000 で起動する
```

店・施設の検索に Google Places API を使う場合は `.env.example` を `.env` に写して
`GOOGLE_PLACES_API_KEY` を設定します。設定しない場合は OpenStreetMap（Overpass API と Nominatim）の
公開サーバーに問い合わせます。鍵を書かなくてもテストは通ります
（外部への問い合わせを差し替えて実行するため）。

## 設計上の判断

同時書き込みへの対処は `src/services/jsonStore.ts` にあります。
保存先を JSON ファイルにした結果、同じファイルへの読み書きが重なると内容が壊れるため、
ファイルごとに直列化のキューを持ち、書き込みは一時ファイルへ出してから置き換えています。
置き換えは他のプロセスがそのファイルを読んでいると失敗することがあるので、
少し待って再試行し、それでも駄目なら直接書き込みます。原子的ではありませんが、
書き込みが失われるよりはましだという判断です。理由はコードのコメントに残しています。

審査での指摘にどう対応したかは[リポジトリのREADME](../README.md#審査での指摘への対応ハッカソン後)に、
残っている課題は[今後の改善点](../README.md#今後の改善点)に書いています。
